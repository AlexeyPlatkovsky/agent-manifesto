# Documentation Maintenance

## Apply When

Use this policy when completed work changes behavior, interfaces, commands, architecture, domain facts, operating
procedures, or other information readers rely on.

Do not apply it when the primary task already updated the authoritative documentation or when the change has no
meaningful documentation effect.

## Policy

- Documentation changes use the project's authoritative documentation as their source and destination.
- Documentation reflects the actual completed change, not a prediction based only on the original request.
- Only affected facts, examples, indexes, and cross-references change.
- Project terminology and established documentation structure remain consistent.
- Policies and procedures remain in their owning landscape artifacts.
- A no-change decision is reported explicitly.
- Unresolved authority, facts, or scope block speculative documentation edits.

## Evidence

Name the documentation checked, what changed or why no change was needed, and anything left unverified.
